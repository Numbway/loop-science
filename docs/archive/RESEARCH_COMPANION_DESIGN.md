# 科研分身框架设计文档

## 一、框架定位

**目标**：不仅是工具，而是硕士研究生的科研分身

### 核心价值
- 🤖 自动复现论文代码框架
- 🧠 主动分析实验结果，基于参考论文给出改进建议
- ⚙️ 异步自主迭代实验，学生离开后持续工作
- 🌳 完整的实验决策树，可观测每一步决策

### 目标用户
- 硕士研究生
- **需求**：快速复现论文、快速迭代改进、科学对比方案
- **设计原则**：对"不太聪明的人"极其友好，每个功能必须简单易懂

## 二、用户旅程

### 阶段1：项目初始化（引导式对话）

系统采用**逐步引导对话**方式，类似设计review，但设置讨论上限防止发散：

```
系统: "嘿，我是你的科研分身👋 让我帮你快速复现论文并找到改进机会。"

问题1: "请上传你要复现的论文PDF"
用户: [上传文件]

问题2: "这篇论文的核心创新是什么？用一句话总结"
用户: [填空] 
系统自动提取关键词

问题3: "你想在哪些方面改进这篇论文？" (单选或多选)
  - 数据处理/增强
  - 模型架构
  - 训练策略
  - 其他
用户: [选择]

问题4: "设定你的目标指标" (示例：准确率达到92%)
用户: [输入目标值]

问题5: "最多尝试多少轮实验?" (默认：5轮)
用户: [数字]

问题6: "有没有想参考的相关论文？(可选)" 
用户: [上传或跳过]

对话结束 → AI自动推荐3篇最相关的参考论文
```

**对话上限机制**：
- 最多6个核心问题
- 如果某个问题需要澄清，最多追问1次
- 之后进入代码框架审核阶段

### 阶段2：代码框架审核

AI生成完整的初始代码框架：
```python
# 系统自动生成的结构
project/
├── data.py (数据加载和预处理)
├── model.py (模型定义)
├── train.py (训练循环)
├── config.yaml (配置文件)
└── eval.py (评估脚本)
```

学生可以：
- ✅ 审查代码
- ✅ 进行小的修改（AI可自动修复合理错误）
- ✅ 点击"开始实验"

### 阶段3：实验迭代循环（异步自主）

#### 3.1 初始实验运行

```
学生点击"开始实验"
  ↓
系统初始化容器环境 + 安装依赖
  ↓
[实验运行中] 
  └─ 进度条: Epoch 5/100 (配合TensorBoard实时曲线)
  └─ 资源监控: GPU使用率、显存占用
  ↓
实验完成 → 生成metrics.json
```

**监控展示**：
- TensorBoard嵌入式查看：loss曲线、准确率曲线、validation监控
- 简单进度条：已完成epoch数 / 总epoch数
- 预计时间：根据前几个epoch的速度估算

#### 3.2 结果诊断与改进（AI自主）

当实验完成时，系统执行：

```
第1步：读取参考论文
  - 论文来源：系统推荐的3篇 + 学生上传的2篇
  - 如果某篇下载失败 → 标记为"待上传"，跳过
  - 本地存储位置：reference_papers/by_keyword/

第2步：分析实验结果
  - 对比：当前指标 vs 目标指标 vs 参考论文水平
  - 诊断失败原因（过拟合、欠拟合、数据不足等）
  - 或诊断性能瓶颈

第3步：生成改进建议
  - 有理由的建议（基于参考论文证据）
  - 包含：改进方法、为什么这样改、预期效果
  - 例：
    ```
    建议1: 加入BatchNorm层
    原因: 检测到模型不稳定(validation loss波动大)
    证据: 参考论文[1][2]都使用了BatchNorm，在ImageNet上稳定性提升8%
    预期: 准确率可能提升1-2%
    
    建议2: 增加数据增强
    原因: 训练集上表现好，验证集表现差(过拟合)
    证据: 参考论文[3]通过RandAugment将准确率从86%提到89%
    预期: 准确率可能提升2-3%
    ```

第4步：自动修改代码
  - 精确修改model.py、train.py或config.yaml
  - 保持原有逻辑完整
  - 生成修改日志文件

第5步：启动下一轮实验
  - 如果：当前指标未达目标 AND 循环轮数未达上限 AND 学生未暂停
  - 则：自动启动下一轮实验
```

**关键：异步模式**
- 学生可以离开、去做其他事
- AI在后台继续运行实验、诊断、改进
- 学生随时可查看实时进度和实验树

#### 3.3 学生交互点

学生可以在任意时刻：

1. **查看实验树** → 看到所有的分支和结果
2. **暂停迭代** → 停止AI自主循环
3. **在某个节点新建分支** → 点击节点的`+`号
   - 输入新的改进想法（类似初始问卷，最多3个问题）
   - AI从该节点代码出发，生成新分支
   - 完全复制该节点的代码 → 修改 → 新分支3-2开始迭代
4. **手动调整参数** → 修改某个节点的代码后重新运行
5. **查看详细报告** → 点击节点链接，打开HTML完整分析

## 四、数据结构与版本管理

### 4.1 Git分支管理

```
main (初始代码框架由AI生成)
  ├── exp/1 (初始实验)
  │   ├── exp/2-1 (改进方案1：+Dropout)
  │   │   ├── exp/3-1 (继续改进：+BatchNorm)
  │   │   └── exp/3-2 (新分支：试试残差连接)
  │   └── exp/2-2 (改进方案2：数据增强)
  └── exp/baseline (用户创建的备选方案)
```

**分支命名规则**：
- `exp/1` → 第一轮实验
- `exp/2-1` → 第二轮的第一个分支
- `exp/3-2` → 从2-1分支出来的第二个子分支

**检出分支时**：
```bash
git checkout exp/3-2
# 此时工作目录 = exp/3-2分支的完整代码
```

## 五、AI核心能力

### 5.1 能力1：论文解析 + 代码框架生成

**输入**：
- PDF论文
- 学生的改进意图（通过引导式问卷收集）

**输出**：
- 完整的、可运行的代码框架
- 数据处理脚本
- 模型定义
- 训练循环
- 评估脚本
- 配置文件

**关键**：代码必须开箱即用，学生审核后可直接运行

### 5.2 能力2：参考论文推荐 + 本地管理

**自动推荐流程**：
1. 从原论文提取关键词和核心概念
2. 搜索学术库（arXiv、Google Scholar、Semantic Scholar）
3. 找到3篇最相关的论文
4. 尝试自动下载

**失败处理**：
- 下载失败 → 标记为`status: "failed"`
- 保存论文元数据
- UI提示学生手动上传
- 学生上传后 → 自动提取关键词、索引

**存储管理**：
- 按关键词分类存储
- 快速检索相关论文
- 诊断时自动匹配

### 5.3 能力3：实验诊断 + 改进建议

**诊断流程**：

```
输入: 实验结果(metrics.json) + 代码(model.py等) + 参考论文(5篇)

第1步：分析指标
  - 准确率涨了吗？
  - Loss在下降吗？
  - 过拟合还是欠拟合？
  - 收敛了吗？

第2步：对比参考论文
  - 这5篇论文的最好结果是什么？
  - 它们用了什么关键技术？
  - 如何在当前代码中应用这些技术？

第3步：诊断问题
  - 如果accuracy没涨 → 可能过拟合/欠拟合/学习率不对/...
  - 如果loss不降 → 可能数据不对/模型不对/超参不对/...
  - 对应到参考论文中解决过的问题

第4步：生成改进建议
  - 每个建议都要有理由和参考论文证据
  - 按优先级排序（高优先级 = 多篇论文都用了 + 效果明显）
  - 预估改进幅度
  
输出: 改进建议列表 + 原因分析 + 参考文献
```

**改进建议格式**：
```
建议1: +BatchNorm
原因: 检测到训练不稳定(validation loss波动大)
证据: 参考论文[1][2][4]都用了BatchNorm
参考: BatchNorm论文报告在ImageNet上稳定性↑8%, ResNet论文报告准确率↑2%
预期: 准确率可能↑1-2%
代码改动: 在model.py中卷积层后加BatchNorm2d

建议2: 增加数据增强
原因: 训练集85%, 验证集82% (过拟合)
证据: 参考论文[3]通过RandAugment从86%→89%
代码改动: train.py中添加augmentation

建议3: 改学习率
原因: loss曲线震荡，可能学习率太高
预期: 可能↑0.5%
代码改动: config.yaml中lr改为0.001
```

### 5.4 能力4：自动代码改进

基于改进建议，AI自动修改代码：

```python
# AI需要能够做到：
1. 在model.py中正确位置加入BatchNorm
2. 在train.py中添加数据增强
3. 修改config.yaml中的超参数
4. 保持原有代码逻辑不破坏
5. 生成修改日志
```

**安全措施**：
- 每次修改前备份
- 修改后进行语法检查
- 如果失败，自动回滚并通知系统管理员

### 5.5 能力5：实验报告生成（HTML）

自动生成包含以下内容的HTML报告：
- 快速总结（一句话结论）
- 详细分析（诊断+改进理由）
- 性能对比表（与之前节点对比）
- 训练曲线（TensorBoard嵌入）
- 代码变更（Diff展示）
- 参考文献（带链接）
- 后续建议

## 六、错误处理策略

### 6.1 环境问题 → AI自动修复

```
场景：缺失依赖包
检测: ModuleNotFoundError
处理: 
  1. 自动安装缺失包
  2. 重新运行实验
  3. 通知: "系统检测到缺失库torch，已自动安装，重新运行中..."

场景：CUDA/GPU问题
处理:
  1. 自动降级到CPU或使用其他GPU
  2. 通知: "GPU不可用，已切换到CPU运行，速度可能较慢"
  
场景：磁盘空间不足
处理:
  1. 清理旧的checkpoint
  2. 或暂停并通知用户清理
```

### 6.2 代码问题 → 清晰提示+建议

```
场景：代码语法错误
显示: 
  ❌ "模型定义有问题：第42行缺少闭括号"
  建议: "请检查model.py第42行附近的代码"
  
场景：配置不匹配
显示:
  ❌ "配置错误：batch_size=256但GPU内存不足"
  建议: "已自动调整batch_size=128，继续运行"
  
场景：不确定的改动
显示:
  ❌ "无法确定是否应该修改xxx"
  建议: "需要你的确认：..." (询问用户)
```

## 九、关键设计原则总结

1. **极简易用**
   - 初始化采用引导式对话（不是配置表单）
   - 结果展示优先简洁总结，详细内容在HTML报告
   - 每个功能尽量一键完成

2. **异步自主**
   - 学生不操作时AI继续工作
   - 学生可随时干预、暂停、新建分支
   - 决策树完全可观测

3. **有理有据**
   - 改进建议必须基于参考论文证据
   - 诊断要解释原因不是只给答案
   - 代码改动可追溯和理解

4. **容错友好**
   - 优先自动修复而不是报错
   - 出错时用人话解释，给解决方案
   - 失败论文有补救机制

5. **完整可观测**
   - 实验树记录每一步决策
   - 每个节点有详细报告
   - 可随时回溯任何分支
